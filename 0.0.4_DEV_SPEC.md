# Version 0.0.4 Development Specification

## Overview
This document details the features and requirements for Workstation CLI v0.0.4. Each feature includes its purpose, expected behavior, and implementation notes.

---

## Feature Specifications

### 1. AI Chat Prompt Context Update
**Purpose:** Clarify the AI's understanding of its environment and capabilities.

**What it does:**
- Updates the system prompt for AI chat interactions to explicitly state that it is running within Workstation CLI
- Specifies that Workstation CLI is an interface for chemistry and AI actions (as documented in the README)
- Ensures AI responses are contextually aware of the CLI environment

**Expected Behavior:**
- AI responses reference "Workstation CLI" when providing help or context
- AI understands it has access to chemistry tools and local model capabilities
- Responses are tailored to the CLI interface rather than generic chat responses

**Implementation Notes:**
- Modify the AI system prompt/initialization code
- Inject context about CLI version, available chemistry tools, and local model status

---

### 2. Smart Screen Clearing / Context Preservation
**Purpose:** Improve UI readability while maintaining calculation context.

**What it does:**
- Clears previous menu/page text when navigating to new options
- Preserves calculation history (e.g., previous steps in molar mass calculations)
- Prevents screen clutter while keeping critical reference data visible

**Expected Behavior:**
- When entering a new menu, only the current page/options are displayed
- When exiting (via main menu or CTRL+C), the screen clears appropriately
- In multi-step calculators (e.g., molar mass calculation), previous steps remain visible for reference
- Users can see the current calculation without scrolling through historical menu navigations

**Implementation Notes:**
- Differentiate between "menu navigation text" (clearable) and "calculation data" (preserve)
- Implement context-aware clearing based on module type (chemistry calculator vs. navigation menu)
- Use `clear()` or `\033[2J` strategically based on context

---

### 3. CLI Information Page Credits
**Purpose:** Give proper attribution to open-source projects and model creators.

**What it does:**
- Adds a dedicated credits section to the CLI Information page
- Credits Ollama for enabling local model support
- Provides universal credit to AI model creators (Gemma, Mistral, etc.)

**Expected Behavior:**
- CLI Information page displays all contributors/credits prominently
- Ollama is specifically mentioned for local model capability
- AI model creators are acknowledged (e.g., "Models powered by Mistral, Gemma, and other community projects")
- Credits section is organized and easy to read

**Implementation Notes:**
- Add credits to the existing info command/page
- Consider a separate "Credits" menu option for detailed information
- Include version numbers or links where appropriate

---

### 4. Breadcrumb Navigation Tab System
**Purpose:** Show users their current location within the CLI hierarchy.

**What it does:**
- Displays a navigation breadcrumb at the top of the screen
- Shows the user's current location in the CLI (e.g., HOME --> Chemistry --> Calculators --> Molar Mass)
- Similar to directory navigation in file systems

**Expected Behavior:**
- Breadcrumb updates dynamically as users navigate menus
- Format: `HOME --> Section --> Subsection --> Current Page`
- Breadcrumb is visible on every page for consistent context
- Users can potentially click/select breadcrumb items to jump to previous levels (optional enhancement)

**Implementation Notes:**
- Maintain a navigation stack/history
- Update breadcrumb on each menu change
- Position at the top of the CLI interface
- Use arrow or forward slash separators for clarity

### 5. README Enhancement with Shields.io Banners
**Purpose:** Improve project presentation and visibility on GitHub.

**What it does:**
- Adds Shields.io badges to the README
- Displays project metadata (language, version, license, etc.)
- Improves visual appeal and professional appearance

**Expected Behavior:**
- README includes relevant badges (Python, Version 0.0.4, License, Build Status, etc.)
- Badges link to relevant resources or services
- Badges are placed prominently near the project title

**Implementation Notes:**
- Use shields.io service to generate badges
- Include: Python version, project version, license, activity status

### 6. Exit Message Personalization
**Purpose:** Improve user experience with a more human and friendly exit message.

**What it does:**
- Replaces formal/scripted exit messages with more personal, conversational language
- Makes goodbye feel natural rather than programmatic

**Expected Behavior:**
- Exit messages are friendly and engaging (e.g., "See you next time!" or "Thanks for using Workstation CLI!")
- Messages vary or feel contextual to the CLI experience
- Tone matches the overall CLI personality

**Implementation Notes:**
- Replace generic exit strings with personalized alternatives
- Optionally randomize messages for repeated use
- Ensure consistency across exit points (main menu, CTRL+C, etc.)

### 7. Periodic Table Feature
**Purpose:** Provide quick access to chemistry reference data within the CLI.

**What it does:**
- Adds a new "Periodic Table" sub-menu to the Chemistry section
- Displays a periodic table of elements (simplified version)
- Shows element properties: atomic number, name, symbol, atomic mass, and other key data

**Expected Behavior:**
- Users can navigate to Chemistry --> Periodic Table
- Periodic table is displayed in a readable format (may be simplified/paginated)
- Users can search or filter elements by name, symbol, or atomic number
- Element details include at least: atomic number, name, symbol, atomic mass
- Optional: categories (metal, non-metal, noble gas), electron configuration, or other properties

**Implementation Notes:**
- Use a periodic table data structure (JSON or CSV)
- Implement search/filter functionality
- Consider pagination or interactive navigation for large datasets
- Format table for CLI display (consider column width and readability)

---

### 8. Input Validation & Error Handling
**Purpose:** Provide robust error handling and user-friendly feedback.

**What it does:**
- Validates user input across all features (chemical formulas, numeric inputs, menu selections)
- Catches invalid inputs before processing
- Displays clear, helpful error messages

**Expected Behavior:**
- Invalid chemical formulas are caught and explained (e.g., "Invalid formula: 'H2O3' might be incorrect")
- Non-numeric input in numeric fields is rejected with a clear message
- Menu selections outside valid range prompt for re-entry
- Error messages guide users toward correct input (e.g., "Please enter a number between 1 and 5")
- Users are never left in a broken state after invalid input

**Implementation Notes:**
- Add input validation functions for common types (formula, number, menu selection)
- Implement try-catch blocks for calculation operations
- Create a consistent error message format

---

### 9. Command History & Shortcuts
**Purpose:** Improve efficiency for repeated calculations.

**What it does:**
- Stores recent calculations or commands in history
- Allows users to quickly re-run previous commands using shortcuts (e.g., `!1` for the last calculation)
- Reduces repetitive data entry for similar calculations

**Expected Behavior:**
- Users can see a list of recent calculations
- Shortcut `!1` re-runs the most recent calculation, `!2` the second-most recent, etc.
- History persists within a session (and optionally across sessions)
- Particularly useful in chemistry calculators where similar operations are common
- Users can clear history if desired

**Implementation Notes:**
- Maintain a history list (deque or list with size limit)
- Parse commands like `!1`, `!2` to retrieve and re-execute
- Consider session-based vs. persistent storage
- Limit history size to prevent memory bloat (e.g., last 20 calculations)

---

### 10. Keyboard Navigation Improvements
**Purpose:** Modernize user interaction and reduce input errors.

**What it does:**
- Adds arrow key support for menu navigation
- Allows users to navigate menu options using Up/Down arrows instead of typing numbers
- Provides visual feedback on the currently selected option

**Expected Behavior:**
- Up/Down arrow keys highlight the next/previous menu option
- Enter key selects the highlighted option
- Alternatively, users can still type the option number for quick selection
- Current selection is visually distinct (e.g., highlighted or marked with `>`)
- Works consistently across all menus

**Implementation Notes:**
- Use a library for keyboard input (e.g., `getch`, `inputimeout`, or `keyboard`)
- Implement highlight logic to show current selection
- Test with different terminal environments
- Maintain backward compatibility with number-based selection

---

### 11. Help/Tooltip System
**Purpose:** Provide in-CLI guidance without overwhelming users.

**What it does:**
- Adds a `?` or `help` command available in most menus
- Displays context-sensitive help explaining available options
- Keeps help concise and actionable

**Expected Behavior:**
- Typing `?` or `help` at any menu shows available options and their purposes
- Help is relevant to the current context
- Help text is brief (1-2 lines per option)
- Help command is always available and clearly documented
- Returns user to the same menu after viewing help

**Implementation Notes:**
- Create a help dictionary/map for each menu
- Intercept `?` and `help` commands globally
- Display context-specific help without breaking the current flow
- Consider a `help` option in menus themselves

---

### 12. Save/Export Calculations
**Purpose:** Allow users to preserve and reference calculation results.

**What it does:**
- Enables users to save calculation results to a file or clipboard
- Particularly useful for chemistry work that needs external reference
- Supports both local file export and clipboard copy

**Expected Behavior:**
- After a calculation, users can choose to "Save" or "Copy to Clipboard"
- File export creates a timestamped text file with calculation details
- Clipboard option copies result to system clipboard for pasting elsewhere
- Export format is human-readable and includes all relevant calculation steps
- Users are shown confirmation of successful save/copy

**Implementation Notes:**
- Use `pyperclip` or `tkinter.clipboard` for clipboard operations
- Create export directory (e.g., `exports/` or `~/.workstation_cli/exports/`)
- Include timestamp, calculation type, inputs, and results in export
- Format export as plain text or Markdown for readability

---

### 13. UI Theme Toggle (Light/Dark Mode)
**Purpose:** Improve user comfort and accessibility with theme options.

**What it does:**
- Adds a settings menu to toggle between Light and Dark color schemes
- Currently implements Light/Dark mode (future versions may add themes)
- Persists theme preference across sessions

**Expected Behavior:**
- Settings menu includes "Theme" or "Appearance" option
- Users can toggle between Light and Dark modes
- CLI immediately applies the selected theme
- Theme preference is saved and restored on next launch
- All text colors, backgrounds, and highlights respect the theme

**Implementation Notes:**
- Define color palettes for Light and Dark modes
- Store theme preference in a config file (JSON or INI)
- Apply theme colors to CLI output using ANSI color codes
- Ensure sufficient contrast for both themes (accessibility)
- Provide sensible defaults based on system theme (optional)
