## Universal Thinking Modes

The reasoning ("thinking") slider **must work with every Ollama model**, regardless of whether the model has native reasoning capabilities.

Implementation requirements:

* The reasoning level is a CLI feature, **not** a model-specific feature.
* Every installed Ollama model must support all four reasoning levels:

  * Minimal
  * Low
  * Medium
  * Max
* Detect whether a model exposes native reasoning or thinking controls.
* If native reasoning is available, use the model's supported reasoning mechanism.
* If native reasoning is **not** available, emulate the selected reasoning level by dynamically modifying the system prompt.
* The user experience must remain identical regardless of the selected model.

### Prompt Behavior

When prompt-based reasoning is required:

* **Minimal**

  * Answer directly.
  * Avoid unnecessary explanation.
  * Minimize internal planning.
  * Optimize for speed and low token usage.

* **Low**

  * Perform light planning.
  * Briefly verify important facts.
  * Keep responses concise while improving accuracy.

* **Medium**

  * Plan before answering.
  * Consider alternative approaches when appropriate.
  * Explain key decisions.
  * Verify calculations and important conclusions.

* **Max**

  * Perform extensive planning.
  * Break complex tasks into logical steps.
  * Consider multiple solutions before selecting the best one.
  * Self-check reasoning for errors or inconsistencies.
  * Produce the most complete, accurate, and well-supported response possible.

### Compatibility

The implementation must never disable or hide the reasoning selector because of the selected model.

Instead:

1. Use native reasoning controls when supported.
2. Otherwise, automatically emulate the requested reasoning depth through prompt engineering.
3. Fall back gracefully without generating warnings or errors.

The reasoning selector should therefore behave consistently across **all Ollama models**, making it a universal CLI capability rather than a model-specific feature.

### Model Preference

When multiple installed models are capable of completing a task:

* Prefer smaller, faster models that can satisfy the requested reasoning level.
* Avoid selecting significantly larger models unless they provide a measurable quality improvement.
* Model selection should balance response quality, latency, and resource usage while respecting the user's chosen model whenever possible.
